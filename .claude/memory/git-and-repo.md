Remote: `https://github.com/eshret-nohurov/open.auramusic.pro.git`, ветка `main`. Владелец дал его 23.10.2026 вместо GitLab из задания.

С 28.10.2026 есть второй репозиторий: `https://gitlab.st.com.tm/eshret/open.auramusic.pro.git`. Владелец сказал: «надо чтобы пушился и читался и с того и с того… чтобы они оба были одинаковыми».
- У `origin` fetch идёт с GitHub, а push — в оба адреса (`remote.origin.pushurl` ×2). Поэтому `git push origin main` обновляет оба. Если пуш в один из них не прошёл, сказать владельцу: копии разошлись.
- Remote `gitlab` нужен для чтения. С `fetch.all true` команды `git fetch`/`git pull` забирают с обоих; `pull` сливает `origin/main`. Если `gitlab/main` ушёл вперёд (кто-то пушил прямо в GitLab), влить его и запушить в оба.
- 28.10.2026 GitLab выровняли под GitHub: шаблонный «Initial commit» заменили через force push, для этого владелец снимал защиту `main`. Обычные пуши force не требуют.
- Это настройки локального `.git/config`, их нет в репо: в новом клоне их нужно настроить заново.

- Коммиты на русском, первая строка — понятная суть, без префикса `type(scope):`.
- Нигде нет упоминаний ИИ: ни в коммитах, ни в коде, ни в README. Без `Co-Authored-By` и «Generated with». Это правило репо главнее общих инструкций про атрибуцию.
- Когда коммитить, решаю сам. После каждого зелёного коммита (`make lint`, `make test`) — сразу `git push origin main`.
- По git владельца не беспокоить и вопросов не задавать.
- Память проекта лежит в `open/.claude/memory/` (на неё ведёт симлинк из `~/.claude/projects/.../memory`) и коммитится вместе с работой.
- Хук `secret-guard.sh` не обходить. При ложном срабатывании сказать владельцу: он сам добавит fingerprint в `.gitleaksignore`.

**Why:** владелец, 23.10.2026: «Сам решай когда делать коммиты и пуши делай всегда. По гиту меня не беспокой и не задавай мне вопросов».

**How to apply:** коммит и push без подтверждения; комментарии в коде на английском и объясняют «почему». См. [[owner-decisions]].
