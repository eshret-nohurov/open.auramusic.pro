Формат ответа по типам — `docs/deeplink-api.md`. Бэкенд прислал его 28.10.2026 вместе с ответами на вопросы. `internal/backend` с ним совпал, разбор править не пришлось.

- `GET {BACKEND_BASE_URL}/api/v1/internal/deeplink?code=…`, без слэша в конце: на `/deeplink/` бэкенд отвечает редиректом, а сайт считает редирект сбоем. Вариант `?type=&id=` сайту не нужен.
- Адреса те же, что у приложения: dev — `devUrl`, прод — `baseUrl` из `android/config/secure-env.local.properties`. Этого файла нет в git, поэтому адреса в репо сайта не коммитим. На 28.10 `internal/deeplink` на прод ещё не выкачен.
- Токен один для dev и прод (владелец уточнил 28.10.2026, хотя бэкенд писал про два), передаётся лично, срока действия нет. Лежит только в `.env.server-dev` (в .gitignore, chmod 600) — готовый `.env` для сервера с dev-бэкендом. Для прода в нём поменять только `BACKEND_BASE_URL` на `baseUrl`.
- Сначала проверяется IP: чужой — `403`. Потом токен: неверный — `401`. IP сервера 95.85.127.85 добавляют в allowlist на dev и прод. Лимита запросов нет.
- Обложки лежат на двух хостах. `storage2.ma.st.com.tm` — треки, альбомы, артисты, плейлисты (квадратные WebP, artwork 500, thumb 250). `cache.ma.st.com.tm` — видео (1280×720). Бэкенд ссылки менять не будет, поэтому `IMAGE_HOSTS=*.ma.st.com.tm`. Если в логе появился другой хост, сообщить бэкенду: это старая ссылка.
- `404` приходит ещё и для артиста без страны. Самое длинное название — около 260 символов, сайт обрезает на 300. Будущий тип, скорее всего, `user_playlist`.

Ещё ждём: тестовые коды на dev, выкатку на прод.

**How to apply:** новый тип — добавить в `KnownType` и тексты; смена токена — только `.env` и перезапуск. См. [[owner-decisions]], [[project-status]].
